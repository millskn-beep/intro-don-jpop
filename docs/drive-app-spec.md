# ドライブ用アニソンアプリ（Apple Music）仕様書・申し送り

作成：2026-10-07（アニソンイントロ対戦の作業チャットから）
状態：**課題として記録しただけ。まだ作っていない**。作成は別のチャットで行う。

---

## 1. 目的

運転中に、アニソンを BGM として流しながら、ときどきイントロクイズを出してくれる Android アプリ。
画面を見たり触ったりしなくても遊べること（ハンズフリー）がいちばん大事。

## 2. 前提

| 項目 | 内容 |
|---|---|
| 使う人 | 本人だけ（Apple Music に個人で契約している） |
| 端末 | Android スマホ |
| 配り方 | APK を直接スマホに入れる（Google Play には出さない・無料） |
| 曲の再生 | Apple Music のフル再生（公式の原曲の音源） |

## 3. できるかどうか（結論：できる。条件つき）

- **Apple Developer Program（年額。2026年時点で約99米ドル）が必須。**
  - Apple Music の曲をアプリから流すには、MusicKit の「開発者トークン」（JWT）が必要。
  - トークンは開発者登録で作る秘密鍵（.p8）で署名する。**Apple Music の契約だけでは作れない**。
  - トークンは最長6か月で期限切れになるので、小さなサーバーで作り直すのが楽。
- **再生のしくみは MusicKit JS（ウェブ版）を使う。**
  - Android の Chrome は DRM（Widevine）に対応しているので、Apple Music のフル再生ができる。
  - 初回だけ Apple ID でログインする。
  - **アプリの形は PWA ＋ TWA（Bubblewrap で APK 化）にする。** TWA は Chrome そのもので動くので再生できる。
  - Capacitor などの WebView 型は DRM で再生できないことがあるので避ける。
- **Android Auto（車の画面）への対応は、この方式ではできない。** スマホから車のスピーカー（Bluetooth）に流す形になる。

## 4. 作るもの（機能）

### 4.1 モード
1. **BGM モード：** アニソンをシャッフルで流し続ける。年代・ジャンル・知名度で絞れる（イントロ対戦と同じ分け方）。
2. **クイズモード：** 数曲に1回、イントロクイズを出す。
   1. 「問題です！」と読み上げる（音声合成）。
   2. イントロを数秒流す。
   3. 声で答える（音声認識）か、大きなボタンで答える。
   4. 正解・不正解と、曲名・作品名を読み上げる。
   5. そのままサビから流し続けて BGM に戻る。
3. **答えだけ聞くモード：** 答えずに聞き流し、10秒後に答えを読み上げる（運転に集中したいとき用）。

### 4.2 ハンズフリーの作り
- 音声合成：ブラウザの `speechSynthesis`（日本語）。読み上げ中は曲の音量を下げる（ダッキング）。
- 音声認識：Chrome の `webkitSpeechRecognition`（日本語）。曲名・作品名・読み仮名（別名）で正解判定（イントロ対戦の判定のしくみを流用）。
- ボタンは画面いっぱいの大きさで、「スキップ」「もう一回」「答え」「一時停止」だけ。
- 自動で次へ進む。操作しなくてもずっと続く。
- 画面を消さない（Wake Lock）。ただし運転中は画面を見なくて済むようにする。

### 4.3 安全面
- 運転中に文字入力が必要な操作は作らない。
- 起動時に「運転中は画面を操作しないでください」と表示・読み上げ。

## 5. データ

- **曲の一覧は、イントロ対戦の `D:\AI\anison\data\songs.json`（約2,400曲）を流用する。**
  - 項目：曲名・作品名・歌手・年・種別・別名・知名度・イントロ秒・サビ秒・サビの出どころ
- **Apple Music の曲ID への紐付けが必要。**
  - Apple Music API（カタログ検索）で「曲名＋歌手」を検索して、`appleId` を足す。
  - TVサイズ・ライブ版・カバー版を取り違えないよう、長さや歌手名で照合する。
  - 見つからない曲は外すか、手で直す。
  - 参考：無料の iTunes Search API（`https://itunes.apple.com/search?country=jp&media=music&entity=song&term=…`）でも「紅蓮の弓矢」など、原曲が見つかることを確認済み。
- **イントロ・サビの秒数は、そのままでは使えないことがある。**
  - いまの秒数は YouTube の動画（MV やノンクレジット映像）に合わせたもの。Apple Music の原曲とは頭の位置がずれることがある。
  - 出どころが「Topic」（公式の音源）の曲は、ほぼそのまま使える。
  - それ以外は、曲の長さの違いから補正するか、アプリ内で直せるようにする。
  - DRM の音源は音の解析ができないので、イントロ対戦の無音カットのしくみは使えない。

## 6. 作り方（構成）

```
別リポジトリ（例 D:\AI\anison-drive）
├─ PWA（HTML/JS）…再生・クイズ・音声合成／認識・画面
├─ 小さなサーバー（Render など）…開発者トークン（JWT）を作って渡すだけ。秘密鍵(.p8)はサーバーの環境変数に置く
├─ data/songs.json …イントロ対戦から取り込み＋appleId
└─ TWA（Bubblewrap）…APK を作る。/.well-known/assetlinks.json をサイトに置く。署名の鍵は大切に保管
```

## 7. 進め方（案）

1. Apple Developer Program に登録し、MusicKit の識別子と秘密鍵を作る（**本人の作業**）。
2. トークンを作るサーバーと、MusicKit JS で1曲流すだけの試作を作り、Android の Chrome でフル再生できることを確かめる。
3. songs.json に appleId を付ける道具を作る（検索→照合→手で直す画面）。
4. BGM モードを作る。
5. クイズモードと音声合成を作る。
6. 音声認識での回答を作る。
7. TWA で APK にして、実際の車（Bluetooth）で確かめる。

## 8. 気をつけること・未確認

- Apple の規約：MusicKit の再生は契約者本人に向けたもの。録音・音源の加工・再配布はしない。個人利用の範囲で使う。
- 音声認識は、走行音や音楽が鳴っている中だと精度が落ちる。ボタンでも答えられるようにする。
- Bluetooth 接続中の音声合成と曲の音量バランスは、実車で確かめる。
- 開発者トークンを画面側に直接書かない（サーバーで作る）。
- 2026年の最新の料金・規約・MusicKit JS の対応状況は、作り始めるときに公式サイトで確かめ直すこと。
