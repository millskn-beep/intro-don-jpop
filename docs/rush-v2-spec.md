# アニソン激アツRUSH 第2弾：パチスロ本格UI＋演出・モード（仕様書・案）

## 目的
RUSH を「ふつうのクイズ画面に演出を足したもの」から、**パチスロ台そのものに見える専用画面**に作り替える。
当たりの予兆・複数のモード・モードの移り変わり（枝分かれ）で、当たるまでのドキドキを長く楽しめるようにする。

## 作るもの
1. **専用UI（RUSH専用画面）**
   - 台の筐体（液晶・左右のランプ・下のボタン）を画像生成（FLUX.2）で作り、そのなかに問題・選択肢・回答を収める。
   - 保留ランプは台のランプとして描く（青・緑・赤・金・虹。色の光り方もアニメーション）。
   - ふつうのモードの画面（キャラ・ログ・レイアウト調整）は出さない。
2. **予兆（あたるかも？）**
   - 問題が始まってから当たりが分かるまでの間に、段階的に予兆を出す：背景の色の変化、ランプの点滅、キャラ（マスコット）のセリフ、画面の揺れ、ステップアップ（1→2→3段階）、群予告・連続予告。
   - 予兆の強さは保留ランプの色と連動（青は弱い、虹は強い）。ただし、ハズレでも出る（ガセ予告）。
3. **モードを複数にする**
   - 通常モード → 「チャンス」「ボーナス待ち」「RUSH」などへ**移行**する。
   - モードごとに背景・音・予兆・当たり確率を変える。
   - 特定のモードから**枝分かれ**して、さらに上位の当たりモード（例：超RUSH）へ入る道を作る。
4. **モードごとの演出**
   - 各モードで、背景映像・ランプの色・BGMの味付け（フィルター・テンポ）・決めゼリフ・カットインを変える。

## 手順（段階に分けて作る）
1. 筐体・ランプ・背景の画像を生成（FLUX.2。ローカル）。
2. 専用画面に作り替える（問題の出し方は今のRUSHのまま）。
3. 予兆の仕組み（サーバーが予兆の流れを決めて、全員に同じ時刻で出す）。
4. モード（状態遷移）の仕組みと、モードごとの演出。
5. 3001番でひとり・複数人で通して遊んで確認。「反映して」を待つ。

## 気をつけること
- 当たり・予兆の決定は今まで通りサーバーが持つ（クライアントが勝手に決めない）。
- 画像が増えるので、読み込みが重くならないよう圧縮して置く。
- スマホでも崩れないよう、画面は台の比率を保ったまま縮める。

## 作り方（参照した方法）
1. 画風：FLUX.2 klein 9B（参照画像つき）。画風見本は、人物が写っていない GPT Image 2.5 の絵（`E:\flux2\ComfyUI\input\gptstyle_day_b.png`）を参照に入れる。

2. キャラ：立ち絵（膝上〜全身、832×1216、seed 11〜）→ 背景を緑（#00FF00）に差し替え → 表情（胸から上、768×768）を作り、緑を抜いて WebP に書き出す（kakemeiyaku の `cast-play-jobs.py` / `play-export.py` と同じ流れ）。
3. 背景：1536×864、スマホ用に960幅も（FLUX.2 klein 4B または 9B）。
4. 年齢層：10歳前後（ちびっこ）〜20代後半（お姉さん）までバラけさせる。実在の人物・既存作品のキャラには似せない。
